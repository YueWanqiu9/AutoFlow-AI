# Demo 截图计划

本目录用于保存 AutoFlow AI V2.0 的真实页面截图。目前没有可用截图，以下文件名仅为拍摄计划；未创建 PNG 占位图或合成界面。

## 六张截图的讲解顺序

| 计划文件名 | 页面与取景 | 必须保留的信息 | 面试讲解重点 |
| --- | --- | --- | --- |
| `home.png` | 演示首页；必要时使用浏览器整页截图 | 项目名称、定位、核心模块、一键运行完整演示入口、技术架构 | 系统把客户需求转为可执行的服务流程 |
| `workflow.png` | 完整 Demo 执行成功后，选择讲解步骤 2「生成工单」 | 客户原文、十步导航、工单编号、初始审核状态 | 同一需求进入工单，再经过补全、运营决策和服务执行 |
| `priority.png` | 运营工作台 → 工单详情 → 优先级管理 | 建议等级、判断依据、来源、最终等级及确认／修改入口 | 规则给出等级，AI 可解释，运营确定最终优先级 |
| `advisor.png` | 运营工作台 → 工单详情 → AI处理建议 | 待补信息、处理步骤、注意事项、来源、采纳／修改／拒绝入口 | 建议需要运营评审，不等于已经执行 |
| `dispatch.png` | 运营工作台 → 人员匹配推荐，展开候选的派单确认区域 | 候选人员、规则评分、匹配理由、确认人和派单原因表单 | 推荐不直接派单，运营核对后确认 |
| `dashboard.png` | 运营工作台 → 运营数据看板 | 工单总数、人员资源、派单及服务指标、模拟数据提示 | 区分工单统计与服务进度，用过程记录支持复盘 |

建议前两张讲解约 1 分钟，中间三张约 3 分钟，最后一张约 1 分钟。单张图只讲一个主要结论，不要求塞入全部页面内容。

## 后续截图准备

本阶段只整理方案，没有启动应用、生成业务数据或操作数据库。实际截图应在后续审核后进行：

1. 使用不含真实数据库、日志或密钥的独立项目副本，保持 `DEMO_MODE=True`。不要在现有业务库中为了截图修改工单。
2. 在演示首页点击「一键运行完整演示」，拍摄首页与流程图；显示“已执行 10 / 10 步”后，导航是回看位置，不是尚未执行的业务进度。
3. 完整 Demo 使用独立演示库，其工单不会出现在运营工作台。要展示可点击的优先级、建议和派单表单，需要在独立副本的工作台使用原有演示入口准备一条练习工单。
4. 工单补齐客户姓名、电话、地址、服务类型和预约时间，并完成必要审核后，分别拍摄优先级、处理建议和候选人员的确认界面。仅使用明确标记的虚构人员与联系方式。
5. Dashboard 截图来自同一隔离副本；保留模拟数据和统计口径提示。无有效耗时样本时保留“暂无数据”，不要手工填写指标。

如果只拍完整 Demo 的只读结果，可用步骤 5、6、7／8 展示优先级、建议和匹配／派单结果，但必须说明是已完成案例回看，不能声称截图包含交互确认过程。

## 截图质量与真实性

- 建议使用桌面浏览器、约 1440 像素宽视口、100% 缩放，保存为 PNG；长页面可整页拍摄，避免文字缩得无法阅读。
- 保留标题、字段名称、数据来源、Demo 标记及必要风险提示，允许裁去无关空白，不修改页面数值或状态。
- 不拍摄密钥、真实客户信息、账号资料或本机个人路径；如画面混入这些内容，应在干净的隔离环境重新拍摄。
- 不将规则来源改成 AI，不把“登记可用”描述为档期已确认，不把模拟时间描述为效率提升。
- 获得真实文件后再在主 README 中嵌入图片；当前只链接本说明，避免出现失效图片。
